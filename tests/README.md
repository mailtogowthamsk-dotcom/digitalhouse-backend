# Testing

Production-ready Vitest foundation for `digitalhouse-backend`.

## Why Vitest

- First-class TypeScript without `ts-jest`
- Fast watch mode and V8 coverage
- Works with this repo’s CommonJS Express sources via Vite’s Node transform
- Same mental model as Vite used by the admin frontend

## Folder structure

```
tests/
  setup/
    env.ts              # safe NODE_ENV=test + dummy R2/JWT/DB defaults
    db.ts               # integration DB connect/skip helpers
  mocks/
    r2.mock.ts          # Cloudflare R2 (S3-compatible) mock
    redis.mock.ts       # Redis contract mock (for future adapter/queues)
    external.mock.ts    # Razorpay, Google Auth, Nodemailer, Expo Push
  helpers/
    http.ts             # Express Response / user mocks
    factories.ts        # domain factories (matrimony section, …)
  unit/
    services/           # pure / mocked-model service tests
    mocks/              # mock contract smoke tests
  controllers/          # HTTP handlers with services mocked
  integration/          # real MySQL — skipped unless opted in
vitest.config.ts
coverage/               # generated by npm run coverage (gitignored)
```

## Scripts

| Script | Command | Purpose |
|--------|---------|---------|
| Unit + controller (default) | `npm test` | Fast suite; integration skipped |
| Watch | `npm run test:watch` | Re-run on change |
| Coverage | `npm run coverage` | HTML + LCOV + text summary → `coverage/` |
| Integration only | `npm run test:integration` | Requires `RUN_INTEGRATION_TESTS=1` + test DB |
| CI | `npm run test:ci` | Coverage with muted watch, suitable for pipelines |

## Coverage report

```bash
npm run coverage
```

Then open:

- Text summary: terminal output
- HTML report: `coverage/index.html`
- LCOV (CI / Codecov): `coverage/lcov.info`

Thresholds live in `vitest.config.ts` (`coverage.thresholds`). Raise them as more modules gain tests.

## Integration database

```bash
# Windows PowerShell
$env:RUN_INTEGRATION_TESTS="1"
$env:TEST_DB_NAME="digitalhouse_test"
$env:TEST_DB_USER="root"
$env:TEST_DB_PASSWORD="secret"
$env:TEST_DB_HOST="127.0.0.1"
npm run test:integration
```

Use a disposable schema — never point at production.

## Mocking patterns

### R2

```ts
import { vi } from "vitest";
import { createR2MockModule } from "../mocks/r2.mock";

vi.mock("../../src/utils/r2Client", () => createR2MockModule());
```

### Redis (future client module)

```ts
import { createRedisMockModule } from "../mocks/redis.mock";

vi.mock("../../src/utils/redisClient", () => createRedisMockModule());
```

### Controllers

Mock the service facade, keep Zod validation real:

```ts
vi.mock("../../src/services/Post.service", () => ({ postService: { createPost: vi.fn(), ... } }));
```

## CI

GitHub Actions workflow: `.github/workflows/backend-tests.yml` (repo root).

It runs `npm ci` / `npm install` and `npm run test:ci` on the backend package.
